## 實作前驗收條件

1. 最終結果列出已通過配置中實際標記的 TensorRT layer index、name、inputs、outputs。
2. bisect 最後一次失敗時，仍回報先前成功配置；forward/reverse、linear/bisect、全層／零層／無成功配置皆有正確行為。
3. 排除 constant、shape／非 activation outputs，保留既有 precision；debug replay 也可正確報告。
4. 實際 TensorRT CLI 驗證與文件說明如何對照 ONNX、如何套用 layer precision。原模型未提供，不宣稱其精度已驗證。

## 設計

搜尋數量是 parsed TensorRT network 的索引範圍，不是 ONNX node 數量；constant 等 layer 會被跳過。最終根據 marker 的已成功邊界重新套用同一標記邏輯，再列出實際 layer。network 在 setup 保存，因此 replay 不執行 process_network 也能產生報告。搜尋失敗沒有成功配置時不列出建議。

## 實作

- `Precision.setup` 保存 parsed network；結束搜尋時以 good 邊界重新套用既有 mark_layers 規則，列出實際標記層的 index/name/input/output。最後候選失敗或 replay 跳過 process_network 都不會誤列候選結果。
- `mark_layers` 回傳排序後實際標記 indices，保留原 precision reset／restore／排除邏輯。
- 修正 bisect 的 `good >= max_layers` 為 `good > max_layers`：恰好全部層才能通過也是有效結果，只有 max_layers+1 sentinel 代表未找到成功配置。
- 新增 CLI 範例及主 README 連結，說明 parsed TensorRT layer 與 ONNX、engine layer 的差別；可由名稱與 tensor 連接定位，再用 --layer-precisions 重建並檢查。

## 真實 CLI／GPU Demo

測試圖為 X[1,1,16,16] → Mul(X,X) 名 square_sensitive → Sqrt 名 sqrt_sensitive → Add(bias=1) 名 offset → Y；ONNX opset17、IR9、FP32。輸入全為300，ORT參考輸出301。

```python
import numpy as np
import onnx
from onnx import helper as h, TensorProto as T
from polygraphy.json import save_json
nodes = [
    h.make_node("Mul", ["X", "X"], ["square"], name="square_sensitive"),
    h.make_node("Sqrt", ["square"], ["root"], name="sqrt_sensitive"),
    h.make_node("Add", ["root", "bias"], ["Y"], name="offset"),
]
graph = h.make_graph(nodes, "overflow", [h.make_tensor_value_info("X", T.FLOAT, [1,1,16,16])],
    [h.make_tensor_value_info("Y", T.FLOAT, [1,1,16,16])],
    [onnx.numpy_helper.from_array(np.array([1], np.float32), name="bias")])
onnx.save(h.make_model(graph, opset_imports=[h.make_opsetid("",17)], ir_version=9), "overflow.onnx")
save_json([{"X": np.full((1,1,16,16),300,np.float32)}], "inputs.json")
```

在 /data/tenserrt/investigations/4616 執行上述程式，再執行：

```bash
export CUDA_VISIBLE_DEVICES=1
export LD_LIBRARY_PATH=/data/tenserrt/toolchains/cuda-12.9/lib
export PATH=/data/tenserrt/venv/bin:$PATH
polygraphy run overflow.onnx --onnxrt --load-inputs inputs.json --save-outputs reference.json
polygraphy debug precision overflow.onnx --fp16 --mode bisect --show-output --save-debug-replay overflow-replay.json --check polygraphy run polygraphy_debug.engine --trt --load-inputs inputs.json --load-outputs reference.json --atol 0.001 --rtol 0.001
polygraphy run overflow.onnx --trt --fp16 --layer-precisions square_sensitive:float32 --precision-constraints obey --load-inputs inputs.json --load-outputs reference.json --atol 0.001 --rtol 0.001
polygraphy inspect model overflow.onnx --show layers
polygraphy inspect model overflow.onnx --display-as trt --show layers
polygraphy debug precision overflow.onnx --fp16 --mode bisect --load-debug-replay overflow-replay.json --check false
```

結果：搜尋3輪全通過，最終首1層並明確列出 Layer0 square_sensitive，X→square。按此名稱重新build／GPU推論，與ORT全部256個值一致，max_abs_error=0。兩種 inspect 指令均成功。Replay從JSON取得三輪結果、不執行false checker，仍列出相同layer。相同 replay 使用baseline只列出首1層的數量，沒有名稱與tensor明細。

此小圖未限制layer precision時也通過（unconstrained.log）；檔名 overflow 是候選圖名稱，不表示實測有 FP16 overflow。這驗證搜尋、報告及重建流程，不宣稱修正了此圖的數值錯誤。原issue的大模型／資料未提供，未驗證其1301層或原任務精度。最後失敗候選與成功邊界不同的情況由回歸測試的bisect threshold2涵蓋。
