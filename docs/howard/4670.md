## 1. reproduce：如何 Reproduce

已讀 issue（OPEN）、comments（空）、timeline（僅 label），PR search 沒有 #4670，沒有重做既有修正。

同一個實際 Detectron2 anchor 測試套用到 baseline worktree；不需要 weights，因為 anchor 座標只取決於 feature-map 幾何：

```bash
cd /data/tenserrt/worktrees/baseline
# 從修正分支複製 test_input_resolution.py 與 test_infer.py，沒有複製實作修正。
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 PYTHONPATH=/data/tenserrt/worktrees/baseline/tools/onnx-graphsurgeon /data/tenserrt/venv-detectron2/bin/python -m pytest samples/python/detectron2/test_input_resolution.py -q
```

原始七項測試：`4 failed, 3 passed`，exit 1；證據 `baseline-final.log`。

- 768×768 應產生 `(147312, 4)` anchors，實際 `(451143, 4)`，對應 1344×1344。
- 768×1024 內部 padding 測試應產生 `(196416, 4)`，仍得到 `(451143, 4)`。
- sample image/config resize 超過 768 時 anchor 流程不拒絕；ImageBatcher 直接 paste 到較小畫布，靜默裁切。
- 原 1344 anchor 及正常 image preprocessing 三項 control 通過。

另外，完整原版推論 CLI 在讀入成功建立的 engine 後報：

```text
AttributeError: 'TensorRTInfer' object has no attribute 'allocations'
```

獨立真實 GPU engine 測試 `test_infer.py` 在 baseline 亦失敗，exit 1，`baseline-infer-test.log`。這是現有 DeviceMem 遷移留下的失效欄位，阻斷本 issue 所需的完整推論路徑。

## 2. dev：問題釐清／解決方法

| 位置 | 改動與理由 | AC |
| --- | --- | --- |
| create_onnx.py:get_anchors | 依 ONNX height/width 精確補零，取代 ImageList 的固定1344 divisibility；超尺寸圖給明確錯誤 | AC-1、2 |
| create_onnx.py:update_preprocessor | 拒絕非固定、非正數或非32倍數的輸入尺寸 | AC-2 |
| image_batcher.py:resize_pad | resize 後超過畫布時報錯，提示調整 config，不靜默裁切 | AC-2 |
| infer.py:infer | 使用目前持有的 DeviceMem.device_ptr 清單，取代不存在的 self.allocations；檢查 execute_v2 結果 | AC-3 |
| README.md | 使用 config resize limits，不需修改外部 export script；提供768完整流程、相同config要求及限制 | AC-2、3 |
| test_input_resolution.py / test_infer.py | 真實 backbone/generator、image preprocessing、輸入驗證及真實GPU engine兩次推論 | AC-1～3 |

Diff review：保留 normalization→零padding 順序；預設1344產生完全相同anchors；未修改weights、plugins、engine精度。範例的既有 bounding-box 欄位在 visualization 中交換後才輸出 XYXY text，reference 比對使用最終 CLI text，沒有把內部欄位當成最終座標。Black 與 `git diff --check` 通過。


## 解決後的 Demo

準備 `model-768.yaml`（由官方 R50-FPN config dump，INPUT.MIN_SIZE_TEST=768、MAX_SIZE_TEST=768、MODEL.DEVICE=cpu、MODEL.WEIGHTS 指向上列weights），以及 `dog-768.jpg`。實際完整命令：

```bash
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 /data/tenserrt/venv-detectron2/bin/python /data/tenserrt/external/detectron2/tools/deploy/export_model.py --sample-image /data/tenserrt/data/4670/dog-768.jpg --config-file /data/tenserrt/data/4670/model-768.yaml --export-method tracing --format onnx --output /data/tenserrt/data/4670/export-768

cd /workspace/tenserrt/TensorRT
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 /data/tenserrt/venv-detectron2/bin/python samples/python/detectron2/create_onnx.py --exported_onnx /data/tenserrt/data/4670/export-768/model.onnx --onnx /data/tenserrt/data/4670/fixed-converted-768.onnx --det2_config /data/tenserrt/data/4670/model-768.yaml --det2_weights /data/tenserrt/models/model_final_f10217.pkl --sample_image /data/tenserrt/data/4670/dog-768.jpg

CUDA_VISIBLE_DEVICES=1 /data/tenserrt/venv-detectron2/bin/python samples/python/detectron2/build_engine.py --onnx /data/tenserrt/data/4670/fixed-converted-768.onnx --engine /data/tenserrt/data/4670/fixed-768.trt

CUDA_VISIBLE_DEVICES=1 /data/tenserrt/venv-detectron2/bin/python samples/python/detectron2/infer.py --engine /data/tenserrt/data/4670/fixed-768.trt --input /data/tenserrt/data/4670/dog-768.jpg --det2_config /data/tenserrt/data/4670/model-768.yaml --output /data/tenserrt/data/4670/fixed-infer
```

四階段 exit 都是0。匯出 script 未修改；輸入 `[1,3,768,768]`，輸出 num/boxes/scores/classes/masks 五個 tensors。Engine 為FP32，build約30.9秒（只記錄實測，不作性能比較）。

相同 exported ONNX 與相同 config 在 baseline converter 產生451143個anchors；baseline engine也能build。原版runner先因allocations錯誤中止，因此比較anchor影響時，兩個engine均使用同一修正版runner，明確隔離runner錯誤。

| --- | --- | --- | --- |
| 偵測數 | 0 | 1 | 1 |
| dog（class16）score | 無 | 0.9614283 | 0.9615222 |
| 最終XYXY box對reference IoU | 無 | 0.99980145 | 1.0 |
| score絕對差 | 無 | 0.00009388 | 0 |
| 28×28 mask | 無 | 全部finite，376像素>0.5 | 未逐像素比較 |

資料：`reference.json`、`comparison.json`、`fixed-infer/dog-768.txt` 與PNG；log：`export-768.log`、`stable-fixed-convert.log`、`fixed-build.log`、`fixed-infer.log`。低分數的第二個class15結果與reference不同；本次不宣稱整個輸出逐元素相同，也不宣稱資料集mAP或mask IoU已驗證。
