## 根因與範圍

`polygraphy/json/serde.py` 的 NumPy encoder 使用 `np.save(..., allow_pickle=False)` 再 base64，decoder 使用 `np.load`。payload 是整份 NPY 檔案，包含 shape、dtype 等標頭，不是純 FP32 buffer。把整份 payload 傳入 `np.frombuffer` 會把標頭也當成數值。

合成張量 shape (1,2,640,640)，共 819200 個 FP32 值，本次標頭為 128 bytes，因此錯誤解碼多出 32 個值；巨大最大值與 issue 截圖一致。合成資料最小值為 0，未重現截圖的負最小值。原始 JSON／模型未提供，不能判定原始模型實際輸出範圍。

這是解碼用法與文件補充，不是 serializer 或 TensorRT 數值計算修正。既有公開 API 原本就可正確還原；沿用現有 API example 08 補充原因、迭代所有 runner／iteration 的讀取片段及 CLI summary，避免另建重複範例。

NPY 標頭長度可變，不能固定跳過 128 bytes。依據：[NumPy 格式文件](https://numpy.org/doc/stable/reference/generated/numpy.lib.format.html)。
